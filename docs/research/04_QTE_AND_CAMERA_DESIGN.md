## Author a contact beat with one readable intent

| Moment | Direction, animation and sound |
|---|---|
| Anticipation | Establish both actors and the clear threat. Use lead shoulder/weight transfer and a short vocal or prop cue. Present the input after the intent becomes readable. |
| Gate | One intent and one compact glyph. Keep motion already underway during the window. Buffer a short lead-in only if an authored action naturally allows it, and reject a button held from dialogue. A slow anticipation can buy readable time without slowing the interface or game globally. |
| Decision | Resolve by the authored branch marker. Cut on movement, an occluding foreground or a prop insert if a cut is needed. Match silhouette, direction, camera side, prop state and screen position across the cut. Fix mismatched feet/root in the clips. |
| Contact and follow-through | Let the opponent, target/prop and camera react coherently on the same contact cue. Use one strong impact sound, quieter cloth/shoe sounds, actor exertion or a stool scrape, and a short recovery pose. Weight comes from reaction and momentum. Brief local hold or shake can help after readability is proven. There is no verified universal Telltale hit-stop duration. |
| Release | Let the listener register the result and return to the scene. Use different recovery audio, pose and next dialogue for a miss. Use the same geography and preserve the actual ending position. |

Minimum convincing package for the first fight: one readable wind-up, a player-directed response, one convincing pair of contact/evasion clips, one synchronised prop/body/audio response and a short reaction before handback. The prototype proves branching and rig playback but needs production blocking, timing and contact work.

## Input acceptance and presentation

- Define stable InputMap actions for dodge directions, hold, confirm/cancel and choices. Gate uses event edges, accepts remapped buttons, ignores echo, and applies neutral/release re-arm so an old advance press cannot also dodge. For stick input, latch at a tuned threshold such as 0.6, re-arm below 0.35 and capture a direction sector with hysteresis. D-pad and keyboard alternatives remain available. These constants are starting design choices.
- Use one controlling input device per gate where appropriate. Track the last meaningful device event and refresh the displayed glyph on rebind. Confirm through actual controller tests since SDL mapping, platform labels and stick behaviour are below the synthetic test seam. Press, hold, directional and targeted prompts each display a verb plus an input. Targeting uses cyclic focus or direct stick/D-pad selection with confirm, and optional mouse hit test. A targeted prop is selected through a scene binding, so UI has no targeting authority.
- Use a monotonic active clock that excludes pause/focus loss. Decide exactly once at the deadline or an accepted event. Specify tie policy (timestamp strictly before deadline), log late inputs, and avoid animation-speed changes as a source of UI wall-time. For hold, account for time from press to release while the gate is armed. Treat wrong directions by beat policy. Default first dodge ignores irrelevant inputs until timeout. Keep mash optional, with a hold or one-press substitute.
- Starting budgets for playtesting only: telegraph 250–400 ms before the first prompt, 1,100–1,400 ms default decision window, 1.5×/2× assist, and optional untimed/autopass. A visible dodge should respond at once or at a tightly authored transfer marker. Aim for visual acknowledgment within the next rendered frame and branch response within the next few. Track per-device miss rates and latency with local QA. If the assisted window extends the pose, use a subtle anticipation loop and a fixed exit pose.
- Put a compact prompt in a shot-specific safe area, with a screen-space fallback. If projected near the target, clamp it away from edges, subtitles, threat and focus actors. Reserve a subtitle lane, use high contrast and legible scaling, a countdown shape plus optional sound, and glyph+verb instead of colour alone. Controller prompts must survive split/expanded UI, different safe areas and captions. Let the player reduce shake, rumble and flashing. Reuse the normal controls and accessibility menu.

## Camera rules for the bar

Start with an establishing two-shot. Cut closer on the threatening motion. Preserve the action axis through dodge and hit. Reserve the prop insert to bridge a meaningful action choice or a difficult handoff. Use `Camera3D.make_current()` for cuts and a single interpolated camera for deliberate blends, interpolating origin, orientation and FOV. Use `Path3D/PathFollow3D` for a genuinely moving shot. Aim via stable local target markers, and perform a visibility check or pre-author alternate angles for movement. A static shot with unobscured hands and feet will communicate a first exchange more reliably than frequent or drifting cuts. Shake is local and optional, and motion belongs to a contact beat rather than continuous noise. Check a 16:9 and a narrow window, both branches, each actor height variant and the prompt/subtitle overlap.
