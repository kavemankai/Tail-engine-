## A · Telltale Explorer

- [Schema and serializer](https://github.com/coccofresco/telltale-explorer/tree/8209d59d5276d1fb33fa5b11502518d54f848c25/docs). Read `FORMAT_CHOREOGRAPHY.md`, `CHORE_DISASM.md`, `FORMAT_ANIMATION.md`, `FORMAT_SKELETON.md` and related scope notes. Early `Chore` reflected fields lead to agent/resource loops. Parsed resources communicate intent with block timing, handle, control animation, groups and properties. Agents bind by name/indices. Later layout handling is code evidence within the stated coverage.
- [Parser](https://github.com/coccofresco/telltale-explorer/blob/8209d59d5276d1fb33fa5b11502518d54f848c25/telltale/meta_chore.py). `telltale/chore.py` exposes the decoder. In `meta_chore.py`, see `ChoreResource`, `ChoreAgent`, `Chore`, `decode_chore_resource`, `decode_chore_agent`, MTRE counterparts, `decode_chore`, `parse_chore`, `extract_handles`. `metastream.py` and `meta_handle.py` separate block framing from asset identity. `meta_chore_leaves.py` includes attachments, walk paths, Rule/LogicGroup and dependency records. `inspect_chore.py::inspect` uses structural parsing plus handle extraction.
- Skeleton and clip parsers are separate, including `telltale/skeleton.py`, `parse_anm_values.py` and phoneme timing support. README explicitly leaves full scene+props-to-glTF scene graph on the roadmap. Checkout lacked a retail test corpus. [Open issue #1](https://github.com/coccofresco/telltale-explorer/issues/1) asks for Definitive Series format support. This reinforces the early corpus boundary.

## B · Telltale Cutscene Editor

- [Editor and player Lua](https://github.com/Telltale-Modding-Group/Telltale-Cutscene-Editor/tree/3fcc2668138eba534b738a22adcc9a053f6339fd/Source/cutscene_editor/Cutscene_Editor). `CutsceneEditor.lua::Cutscene_Save`, `Cutscene_Load_Clip`, `Cutscene_Load_Agent`, `AnimationPrewierPlay` implement in-game editing, preview and numbered clip persistence. `LIP.lua::load/save` serialises INI sections rather than original choreography files. See `Demo_Scene/Scene_S2.lua` for scene and resource-set registration, camera prop creation and `CameraPush`.
- `CutscenePlayer.lua::CutscenePlayer` loads separate clip/agent/index tables. `CutscenePlayerUpdate` registers with `Callback_OnPostUpdate`, compares `GetTotalTime()` against clip duration, and routes to `next_clip` or `next_choice1..4`. It resets controllers, updates pose/position (including interpolation or controller-driven modes), applies camera transform, draws and times a choice UI, and checks hardcoded input. Around lines 750–756, voice sound and accompanying acting are launched together. This is explicit clip chaining, not sample-accurate audio scheduling or a general arbitrary-condition system.
- Dependency on the proprietary host is essential. Recent GitHub issue listing was empty and upstream directs mod support to Discord. The software licence does not extend to game assets used in its demo. Design worth taking forward is the distinct scene binding, clip definitions and transition table.

## C · Telltale Editor

- [Common implementation](https://github.com/LucasSaragosa/Telltale-Editor/tree/347e5e6b58c8bbea9643b2d633cceda119fc7b83/TelltaleEditor/Source/Common/Source). `Common/Chore.cpp` maps normalised resource/agent data through `RegisterScriptAPI`, `EmplaceResource`, `EmplaceAgent` and `_DoLoadDependentResourcesAsync`. `Common/Animation.cpp` is animation value decoding/playback support. `AnimationManager.cpp::Mover::_Update` blends relative and absolute components and calls `Scene::UpdateNodeLocalTransform`; `AddAnimatedValue` connects values to playback controllers. `Common/Scene.cpp` and `SceneModules.cpp` contain scene graph and modules.
- `Runtime/SceneRuntime.cpp::AsyncUpdate` drains scene messages. `AsyncProcessGlobalMessage` resolves scenes with a handle and runs an entry point. Input is fanned to scenes, yet `Scene::AsyncProcessEvents` is empty and the per-scene render-message handler returns false. `LuaGameEngine.cpp` and `ToolLibrary/Source/Scripting/{LuaManager,EngineLuaAPI,LibraryLuaAPI}.cpp` expose script plumbing. `ToolLibrary/Source/Resource/ResourceRegistry.cpp` and `Meta/Meta.cpp` deal with asset identity and reflection. This is materially more than extraction, but no demonstrated full retail dialogue/QTE loop.
- [UI and build](https://github.com/LucasSaragosa/Telltale-Editor/tree/347e5e6b58c8bbea9643b2d633cceda119fc7b83/TelltaleEditor/Source). The older ImGui `Editor/Source/UI/UIChore.cpp` draws a timeline and handles resource preview. Top-level subproject CMake comments out the old Editor target and includes EditorQt, so that source is not evidence of a finished shipping Qt chore editor. Relevant [PR #17](https://github.com/LucasSaragosa/Telltale-Editor/pull/17) covers common classes; open issue #21 was withdrawn and provides no compatibility evidence.

## D · TelltaleToolKit

- [Core library](https://github.com/iMrShadow/TelltaleToolKit/tree/07447b60c7ce473210b44350bb1d6031ebc14d8d/src/TelltaleToolKit). `IO/Archives/Formats/TTArchive2.cs` indexes entries and has `Create` paths. `Meta/Serialization/Binary/BinaryMetaStreamReader.cs::BeginBlock/EndBlock` and typed serializers separate file structure from object types, with version/reflection support via `Meta/Reflection/MetaClassRegistry.cs` and associated metadata.
- `T3Types/Chores/{Chore,ChoreResource,ChoreAgent,CameraSelect}.cs` supplement the older fields, including resource time blocks and camera symbols. `T3Types/Dialogs/Dlg/Nodes/{DlgNodeChore,DlgNodeConditional,DlgNodeChoices,DlgNodeScript,DlgNodeSequence}.cs` and `Conditions/{DlgConditionTime,DlgConditionInput,DlgConditionRule}.cs` add especially valuable evidence for a separate authored graph. These are metadata-bearing definitions. `DlgConditionInput` itself contains only the base condition field. There is no shipped QTE evaluator established by these classes.
- [Issue #25](https://github.com/iMrShadow/TelltaleToolKit/issues/25) and [PR #26](https://github.com/iMrShadow/TelltaleToolKit/pull/26) point to archive/profile corrections for TWD S2. Such work is different from compatibility with a gameplay runtime.

## E · Godot Event Sequencer

- [Runtime and editor](https://github.com/Amethyst-szs/godot-event-sequencer/tree/12c7c3e52743116c5b9d3a33b3ff796daa55328a/addons/event_sequence). `node/event_node.gd::start/start_from_label/_preload_scripts_and_labels/_run_dictionary_list` instantiate `EventItemBase` scripts and await their `run()` response. Supports nested branches, conditions, label jumps, loops, timer/frame and signal waits. Dispatch can execute a large non-yielding chain in one frame. `dict_list.find(event)` inside the preload loop can scan repeatedly. No frame cost was inferred from the upstream benchmark.
- `plugin.gd::_enter_tree/_selection_changed` adds a main editor screen. `view/editor.gd::save/_build_dict_from_tree/_try_build_tree` serialises a tree to the node's exported nested dictionaries with short structural keys. This is a visual command list with macros and parameter metadata. It lacks shot/actor track scrubbing. Headless import exercises plugin initialisation. Interactive editor drag/drop was not checked.
- `item/method/call_3_args.gd::run` and sibling method events call AnimationPlayer and Camera3D generically, demonstrated in 05. They do not align actor motion, camera and sound by a shared media clock. Custom async event tested. Plugin camera adapters target CameraAction **2D** and start disabled. Optional dialogue, savedata, sound and wipe adapters are gated by prerequisite configurations. `plugin/dialogue/script/wait_title.espdisabled` uses `passed_title`; current tested DM uses `passed_cue`. Match the deployed DM version before migrating a seam.
- Lifecycle risks from source: `end_force` sets a flag without interrupting a suspended await. Early loop returns can bypass normal cleanup. `wait_any.gd` passes the array rather than the current item in its array branch and its callback connections are not one-shot. Generic script and method events are broad surface area for scene authoring. Only trusted, reviewed resources belong in a release. [Recent issues/PRs](https://github.com/Amethyst-szs/godot-event-sequencer/issues?q=is%3Aissue) offer little recent maintenance signal. Use core code as a reference for awaited event interfaces.

## F · Godot Quick Time Events

[Implementation](https://github.com/Haskerimk/Godot-Quick-Time-Events/tree/cc265af87fb75e23be890552bcf731ec3e8b4957/addons/GD-QTE). The shared `AbstractQTEClass.gd` extends TextureProgressBar with RichTextLabel, a Timer and signals `launched`, `success`, `failed`. Visual polish and choice/navigation are outside it. No native actor or animation interface. Consumers connect signals. The demo fixture uses those signals directly.

| Source | Actual input and time logic | Production consideration |
|---|---|---|
| `CountdownQTE.gd::qte_input_handle` | Successful if configured action is just pressed before timer expiry; UI mirrors remaining time. | Reads `input`, not `selected_input`; random mode divergence. Override skips base `launched`. |
| `TimedQTE.gd::qte_input_handle` | Oscillating progress bar and success range around midpoint. | `range_offset` unused. Sign changes mutate drain setting and can persist between launches. Defaults require explicit tuning. |
| `HoldQTE.gd::qte_input_handle` | Held action adds progress while drain reduces it. | Threshold checked before adding. The default starting value/margin can resolve without input. |
| `MashQTE.gd::qte_input_handle` | Adds progress on mapped press edges, with drain and threshold. | Same default threshold issue. Bar tuning and practice timing matter. |
| `SequenceQTE.gd::_input` | Explicitly requires InputEventKey, then compares mapped event in order. | Keyboard-only. Replace input filter and per-item glyphs, handle echo/release, mismatch policy, fresh launch state and cancellation. Retry can start more waiting coroutines. |

Common issues observed or read: global time scale 0.5 then hard reset to 1.0, a timeout callback **and** an awaited timeout calling failure, missing outcome idempotency, random index upper bound `size()` inclusive, specialised icons referring to `res://QTEV2/Icons` rather than shipped directory. Latest checked issue [#1](https://github.com/Haskerimk/Godot-Quick-Time-Events/issues/1) was about attributes. For a throwaway sequence demo, event matching then glyphs are small changes. For production, replacing clock, lifecycle, accessibility, routing and UI makes a custom director gate simpler.

This search covered GitHub, Godot's Asset Library and store, production talks, developer interviews and gameplay references.
